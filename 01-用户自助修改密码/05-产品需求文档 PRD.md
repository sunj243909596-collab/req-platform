## 1. 摘要（Executive Summary）

为了让所有 Req Platform 用户在**不依赖 ADMIN** 的前提下自助修改自己的登录密码，同时为后续 GSP 05805 审计、合规强改 / 定期改密、忘记密码邮件等流程打下基础，本期交付：

1. 用户自助改密端点 `POST /api/me/password`（需旧密码）
2. 前端用户菜单新增"修改密码"入口及 Dialog
3. 数据库 `User` 表增加 6 个安全相关字段（含本期未消费的 3 个预留字段）
4. 改密成功 → 旧 JWT 立即失效（`tokenVersion` 机制）
5. ADMIN 改密路径保留 + 完善审计
6. 密码相关行为全过程进入 `ActivityLog`

不做：邮件通知、忘记密码真实邮件流、双因子、历史密码去重。

## 4. 交互细节

### 4.1 触发

- 用户菜单 → "修改密码"（**所有**已登录用户均可见）
- 强制改密场景（v1.1）在登录成功后路由层拦截，本期不消费

### 4.2 输入约束

| 字段 | 规则 |
|---|---|
| 当前密码 | 服务端校验，错误时不区分"用户不存在"和"密码错" |
| 新密码 | 长度 ≥ 8，必须包含大小写字母 + 数字 |
| 确认密码 | 必须等于新密码（前端提前校验，降低无效请求） |
| 新 ≠ 旧 | 强制约束，避免"形式改密" |
| 显示密码 | 提供单只眼睛切换，纯 UI（前端不存任何密码到 localStorage） |

### 4.3 强度条（5 段）

| 段 | 触发条件 |
|---|---|
| 弱（红） | 命中 0~1 条 |
| 中（橙） | 命中 2 条 |
| 强（绿） | 命中 ≥ 3 条 + ≥ 8 位 |

判定维度（前端即时）：长度 ≥ 8 / 含大写 / 含小写 / 含数字 / 含特殊字符

### 4.4 成功反馈

- Toast：⏳ 提交中 → ✅ "密码已修改，请重新登录"
- 1.5s 后自动跳 `/login`
- Toast 内提供 "取消去登录" 5s 可点；点了 → 立即登出
- 不强制用户立刻重登，但服务端已使其旧 token 失效（每次下一请求都会 401 → 自动登出）

### 4.5 失败反馈

| 错误 | 表现 |
|---|---|
| 旧密码错 | 当前密码字段下方红字 + Toast（仅提示一次） |
| 强度不够 | 新密码字段下方 + 强度条同步变灰 |
| 两次不等 | 确认密码字段下方红字 |
| 限流 | 整 Dialog 顶部红 banner + "请 Xs 后重试" |
| 网络断 | Toast + 按钮恢复可点 |

## 6. 边界条件 & 异常路径

| 条件 | 行为 |
|---|---|
| 同时开两个浏览器标签 A 改密 / B 停留 | B 标签下次请求自动 401 → 拦截器清 token → 跳登录 |
| 自助改密 1 分钟内第 4 次请求 | 429 + 提示 "操作频繁，请稍后再试" |
| ADMIN 重置自己 | 走 ADMIN 路径，等同 `PUT /:id/password`（v1 + `mustChangePassword=true`） |
| ADMIN 已停用（`isActive=false`）的用户尝试登录 / 改密 | 登录拒绝 + 改密拒绝（`USER_DISABLED`） |
| 改密接口被 CSRF | 当前 `Content-Type: application/json` + SameSite cookies + JWT 双重防御；不改 |
| 改密时用户已无 `isActive`（被 ADMIN 在改密瞬间停用） | 改密成功（事务内隔离），下次请求落 `USER_DISABLED` 拦截 |

## 8. 客服与运营

| 场景 | 客服话术 |
|---|---|
| 用户问"怎么改密码" | "登录后右上角头像 → 修改密码" |
| 用户反映"提交后没反应 / 接口 500" | 让用户截图 Network 面板，看 401/400/429 |
| 用户反映"改完密码旧页面没退出" | 正常现象，下次任意操作会自动登出；如需立即退出，等 1.5s 或手动点 Logout |
| 用户问"忘了当前密码" | v1 暂不支持自助找回，需要联系 ADMIN 走控制台重置；v1.1 提供邮件找回 |
