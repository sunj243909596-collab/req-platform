# 需求管理平台 — 产品设计方案 V3.0 (通用型)

> 版本：V3.0 | 日期：2026-05-18 | 作者：黄噜噜
>
> 定位变更：从 WMS 专用 → **通用需求管理平台**（对标 TAPD / Teambition）
> V3.0 基于 V2.2/V2.3 确认的技术架构，整合评审结论，形成最终完整版。

---

## 一、产品定位

**一句话**：轻量级通用需求管理平台，聚焦「需求记录 + 发版计划 + 团队协作」，不替代重型 PMS，做 TAPD/Teambition 的核心子集。

### 1.1 核心能力

| 能力 | 说明 |
|------|------|
| 📝 需求管理 | 需求/缺陷/任务的全生命周期管理（CRUD、状态流转、子任务、关联、评论） |
| 🚀 发版计划 | 版本规划、需求归属、进度追踪 |
| ✅ 发版审核 | 发版前自动校验 + 审批流程（特色功能） |
| 👥 团队协作 | 用户管理、组隔离、角色权限、通知 |
| 🔧 自定义字段 | 组级别自定义需求表单 |
| 🏗️ 工作流配置 | 组级别自定义状态和流转规则 |

### 1.2 不做的事

- ❌ 不做甘特图（Phase 2 之后按需）
- ❌ 不做统计报表（Phase 2 之后按需）
- ❌ 不做 Wiki / 文档协同
- ❌ 不做 CI/CD 集成

## 二、用户角色与权限

### 2.1 角色定义

| 角色 | 权限 |
|------|------|
| **ADMIN** | 全局管理：用户/组/自定义字段/审核人配置、查看所有数据 |
| **GROUP_LEAD** | 组内管理：创建/编辑/分配需求、创建/管理发版、提交审核 |
| **MEMBER** | 组内操作：查看组内需求、创建需求（如允许）、编辑自己负责的需求、评论 |

### 2.2 数据隔离

- **ADMIN**：查看所有组数据
- **GROUP_LEAD**：查看并管理所属组数据
- **MEMBER**：仅查看所属组数据，编辑自己负责的需求

## 三、核心功能模块

### 3.1 需求管理

#### 3.1.1 需求列表

| 列 | 说明 | 示例 |
|----|------|------|
| 编号 | 自动编号 | REQ-001 |
| 类型 | REQUIREMENT / BUG / IMPROVEMENT / TASK | 需求 |
| 标题 | 需求标题 | 支持扫码入库 |
| 模块 | 业务模块 | 入库管理 |
| 优先级 | P0 / P1 / P2 / P3 | P0 |
| 状态 | 自定义（默认：待评审→评审中→设计中→开发中→测试中→已完成） | 开发中 |
| 负责人 | 分配给谁 | 张三 |
| 所属发版 | 归属的版本号 | V2.3.0 |
| 标签 | 多维分类 | ["GSP", "追溯"] |
| 更新时间 | 自动 | 2026-05-18 |

**操作**：新建、编辑、删除（软删除）、批量操作、搜索、筛选（按类型/优先级/状态/负责人/发版/标签）、排序。

#### 3.1.2 需求详情

Tab 结构：

| Tab | 内容 |
|-----|------|
| **详情** | 标题、类型、优先级、状态、负责人、提出人、期望日期、所属发版、标签、背景、描述、设计方案 |
| **子任务** | 子任务列表（标题、状态、负责人），支持增删改 |
| **评论** | 讨论区，支持 @提及，按时间正序 |
| **关联** | 关联的其他需求（阻塞、依赖、重复等关系） |
| **文档** | 关联的文档（BRD/FSD/PRD 等） |
| **附件** | 上传的文件/图片 |
| **日志** | 操作历史（谁在什么时候改了什么字段） |

#### 3.1.3 状态流转

默认工作流：

```
待评审 ──→ 评审中 ──→ 设计中 ──→ 开发中 ──→ 测试中 ──→ 已完成
                                                        │
                                                  ──→ 已取消
```

- 支持组级别自定义工作流（WorkflowConfig 表）
- 流转时可记录变更原因
- 状态变更自动记录到 ActivityLog

#### 3.1.4 需求关联

支持以下关系类型：

| 关系类型 | 说明 |
|---------|------|
| BLOCKS | 阻塞（A 阻塞 B，A 完成前 B 不能开始） |
| DEPENDS_ON | 依赖（B 依赖 A，A 完成后 B 才能开始） |
| DUPLICATES | 重复 |
| RELATED | 相关 |
| PARENT_CHILD | 父/子（通过子任务实现） |

#### 3.2.1 发版状态流转

```
规划中 ──→ 开发中 ──→ 待审核 ──→ 已发布 ──→ 已关闭
   │                      │
   └──────→ 已取消 ←──────┘
```

#### 3.2.2 发版列表

| 列 | 说明 |
|----|------|
| 版本号 | V2.3.0 |
| 发版名称 | 扫码入库增强 |
| 状态 | 开发中 |
| 需求进度 | 3/5 已完成 (60%) |
| 负责人 | 张三 |
| 计划日期 | 2026-06-15 |

#### 3.2.3 发版详情

- 基本信息（版本号、名称、状态、负责人、计划/实际日期、发版说明）
- 进度统计（按状态分布的条形图）
- 包含的需求列表（支持添加/移除需求）
- 提交审核按钮

### 3.3 发版审核（特色）

#### 3.3.1 审核流程

```
开发中 ──提交审核──→ 待审核
                        │
              ┌─────────┼─────────┐
              ▼         ▼         ▼
           审核通过    驳回修改    直接关闭
              │         │         │
              ▼         ▼         ▼
           已发布    开发中      已关闭
```

#### 3.3.2 审核通过条件（系统自动校验）

- 发版内所有需求状态均为「已完成」或「已关闭」
- 无 P0 优先级需求处于未完成状态
- 可配置：「所有需求完成」或「P0 完成即可」（管理员配置）

#### 3.3.3 审核记录

- 提交时间、审核人、审核动作（submitted/approved/rejected）、审核意见
- 审核通过后自动记录发布时间和审核人

### 3.4 用户与组管理

#### 3.4.1 组管理

- 创建/编辑/删除组
- 删除组时检查组下是否有用户，有则禁止删除

#### 3.4.2 用户管理

- 创建/编辑/禁用用户
- 分配角色（ADMIN / GROUP_LEAD / MEMBER）
- 分配所属组

| 字段配置 | 说明 |

### 3.6 通知系统

| 触发场景 | 通知类型 | 通知对象 |
|---------|---------|---------|
| 需求被分配 | ASSIGNED | 被分配人 |
| 状态变更 | STATUS_CHANGED | 提出人、负责人 |
| 被评论 | COMMENTED | 需求参与者 |
| @提及 | MENTIONED | 被提及人 |
| 发版提交审核 | REVIEW_SUBMITTED | 审核人 |
| 审核结果 | REVIEW_RESULT | 发版负责人 |

### 3.7 AI Agent（特色功能）

#### 3.7.1 定位

内置 AI Agent + 知识库，在需求全生命周期提供智能辅助：**去重、相似检索、方案生成、可行性评估、排期建议**。

#### 3.7.2 知识库

| 知识源 | 内容 | 用途 |
|--------|------|------|
| 历史需求 | 平台内所有需求（标题、描述、方案、评论） | 相似检索、去重 |
| 设计文档 | BRD/FSD/PRD 等产物 | 方案模板参考 |
| WMOS 代码仓库 | 后端 WMS/MGT、PC/PDA 前端源码 | 功能模块分析 |
| WMOS 知识库 | 表结构、GSP 法规、字段映射 | 技术上下文 |

#### 3.7.3 交互入口

| 入口 | 触发方式 | 说明 |
|------|---------|------|
| **创建需求自动分析** | 创建需求后自动触发（异步） | 检索相似需求、检测重复、生成方案初稿、可行性评估 |
| **需求详情 AI 助手** | 需求详情页侧边面板 | 上下文感知问答（涉及哪些表？类似实现？） |
| **独立 AI 对话页** | 侧边栏导航入口 | 自由对话，结合 WMOS 知识库回答技术问题 |
| **排期辅助** | 发版详情页 | 工作量预估、依赖分析、排期建议 |

#### 3.7.4 创建需求自动分析

```
用户创建需求 → 后台异步分析:
  1. 向量检索 Top 10 相似历史需求
  2. 重复检测（相似度 > 0.92 告警）
  3. 检索 WMOS 知识库相关文档
  4. LLM 生成：可行性评估 + 方案初稿
  5. 结果展示在需求详情页顶部横幅
```

#### 3.7.5 不做的事

- ❌ 不做 Agent 自动修改需求内容（仅辅助建议）
- ❌ 不做 Agent 自动分配需求（保留人工决策）
- ❌ 不做代码自动生成（Phase 2 后按需）

### 4.3 部署策略

- **初期**：本地开发机，Docker Compose 启动 PG，Node.js 直连
- **后期**：内网服务器，仅修改 DATABASE_URL 环境变量
- 默认 localhost 调试，支持 CORS 配置

## 六、总结

| 对比维度 | TAPD | 本平台 |
|---------|------|--------|
| 搭建成本 | 注册即可 | 需部署（但一次搞定） |
| 发版审核 | ❌ | ✅ 特色功能 |
| AI 智能分析 | ❌ | ✅ 去重+方案生成+可行性评估 |
| 知识库检索 | ❌ | ✅ WMOS 全量知识库 RAG |
| 自定义工作流 | ✅ | ✅ 支持 |
| 自定义字段 | ✅ | ✅ 支持 |
| 离线/内网 | ❌ SaaS | ✅ 本地部署 |
| 轻量化 | 重 | 轻 |
| 专注度 | 全能型 | 需求+发版+AI辅助 |

本平台的核心价值：**轻量、可定制、内网可部署、AI 智能辅助 + 发版审核为双特色**，专注解决「需求记录 + 发版追踪 + 智能分析」的核心场景。
